# SongSwapBot — телеграм-бот караоке-свопов

Люди приносят песни, шайтан-машина случайно решает, кто чью песню поёт, и выбирает
одну конкретную песню из принесённых этим человеком. По механике это «Тайный Санта»,
где вместо подарков — песни.

- **Стек:** TypeScript + [grammY](https://grammy.dev) + Cloudflare Workers + D1 (SQLite)
- **Хостинг:** бесплатный тариф Cloudflare (100 000 запросов/день — с огромным запасом)
- **Принцип:** вебхук, никакого polling и постоянно работающего процесса

---

## 1. Механика одного свопа

1. **Админ** открывает новый своп — все данные предыдущего свопа удаляются безвозвратно.
2. **Участники** скидывают боту песни (в группе или в личке). Первая песня автоматически
   делает человека участником.
3. Админ **закрывает приём заявок**.
4. Админ **запускает жеребьёвку**:
   - участники случайно разбиваются на **взаимные пары** и меняются песнями
     (А поёт песню Б, Б — песню А; никто не поёт свои);
   - при нечётном числе участников последний без пары поёт случайную песню
     случайно выбранного участника — это единственный случай, когда песни
     одного человека поют дважды;
   - у каждого «поставщика» из его списка выбирается одна случайная песня.
5. Все получают результаты (формат зависит от режима свопа — см. ниже).

Пример: Вася, Петя и Маша принесли по 3 песни (нечётное число). Жеребьёвка: Вася и
Петя поменялись — Вася поёт «Медляк» (принёс Петя), Петя поёт «Лесник» (принёс Вася);
Маше без пары выпала случайная песня — «Кукла колдуна» (принёс Вася, его песни в
этом раунде поют дважды).

## 2. Режимы свопа

Режим определяется **командой админа в групповом чате**: `/newswap` — публичный,
`/newsecret` — секретный. Создание из лички отклоняется подсказкой.

| | Публичный (`public`) | Секретный (`secret`) |
|---|---|---|
| Где создан | `/newswap` в групповом чате | `/newsecret` в групповом чате |
| Приём песен | в группе **и** в личке | только в личке (в группе бот переадресует) |
| Видимость песен до жеребьёвки | открыты всем (публично в `/status`) | каждый видит только свои |
| Анонсы | постятся в группу | нейтрально в группу + лично каждому |
| Результаты | полная таблица пар в группу + каждому его пара в личку | только каждому в личку его пару |

Свопы могут идти **параллельно — по одному на чат**. Оба режима создаются в групповом
чате (из лички бот отвечает подсказкой): `/newswap` открывает публичный своп этой
группы, `/newsecret` — секретный; каждый заменяет только прежний своп своего чата.
Сообщения из группы попадают в её собственный своп.

**Членство:** участвовать в любом свопе могут только участники чата, где он стартовал.
При заявке из лички бот проверяет это через `getChatMember` (заявки из самой группы
проверкой не нуждаются); ошибка API (например, бота удалили из чата) трактуется как
«не участник».

## 3. Команды

| Команда | Где | Кто | Что делает |
|---|---|---|---|
| свободный текст (не `/…`) | личка | все | добавить песни: каждая строка сообщения = отдельная песня |
| `/add Исполнитель — Песня` | личка и группа | все | то же самое, явным образом; несколько песен — по одной на строку |
| `@SongSwapBot Исполнитель — Песня` | группа | все | то же самое (упоминание; многострочно тоже работает) |
| `/status` | личка | все | все твои свопы: участники, твои песни (в публичном — все песни), жребий |
| `/leave` | везде | все | выйти из свопа, мои песни удаляются |
| `/help` | везде | все | список команд; админские показываются только админам |
| `/newswap [название]` | группа | админ | открыть публичный своп этого чата (заменяет прежний, с подтверждением кнопкой) |
| `/newsecret [название]` | группа | админ | открыть секретный своп этого чата (заменяет прежний, с подтверждением кнопкой) |
| `/close` | везде | админ | закрыть приём заявок |
| `/draw` | везде | админ | жеребьёвка; повторный вызов = перерозыгрыш (с подтверждением) |

Админ умеет всё то же, что обычный пользователь. Админы — список Telegram user ID
в секрете `ADMIN_IDS` (см. раздел «Конфигурация»).

Несколько параллельных свопов: действия из лички (песни текстом, `/leave`, `/close`,
`/draw`) при неоднозначности уточняются кнопкой. Песни из лички по умолчанию идут в
единственный подходящий своп — сначала тот, где ты уже участвуешь, затем единственный
открытый публичный; секретные свопы всегда выбираются явно.

Админ-команды (`/newswap`, `/newsecret`, `/close`, `/draw`) не-админам не показываются:
в `/help` соответствующая секция видна только админам, при создании свопа шпаргалка
с командами приходит админу в личку, а анонсы в чат свопа идут без команд.

Формат песни — свободный текст «Исполнитель — Название», одна песня на строку.
Пустые строки и пробелы обрезаются. Лимита на количество песен нет.

## 4. Состояния и правила

```
collecting ──/close──▶ closed ──/draw──▶ drawn
     ▲                    │                  │
     └──── /newswap ──────┴──────────────────┘   (старый своп удаляется, новый = collecting)
```

- В `collecting` разрешены: добавление песен, `/leave`, `/close`, `/newswap`, `/newsecret`.
- В `closed` запрещены: добавление песен и `/leave` (состав зафиксирован).
  Разрешены: `/draw`, `/newswap`, `/status`.
- В `drawn` разрешены: `/status` (с результатами), повторный `/draw` (перерозыгрыш
  с подтверждением), `/newswap`.
- `/newswap` и повторный `/draw` — деструктивные, всегда с inline-кнопкой подтверждения.
- `/draw` при < 2 участниках — ошибка с объяснением.
- Свопы параллельны: в каждой группе — свой; `/newswap` затрагивает только свой чат.
- В публичный своп попадают только участники чата свопа (проверка `getChatMember`
  на заявках из лички).
- Дубликаты песен у разных людей допустимы: двое могут спеть одно и то же — это фича.
- `/status` работает только в личке (в группе бот отвечает подсказкой перейти в личку).

## 5. Алгоритм жеребьёвки

1. Взять всех участников активного свопа (n ≥ 2) и случайно перемешать.
2. **Взаимные пары**: перемешанный список режется на последовательительные пары,
   в каждой паре участники меняются песнями (А поёт случайную песню Б, Б —
   случайную песню А).
3. **Чётное n**: пары покрывают всех — каждый поёт одну чужую песню, и его песни
   поют ровно один раз.
4. **Нечётное n**: первые n−1 участников разбираются в пары так же, а последний
   без пары поёт случайную песню случайно выбранного участника. Песни этого
   «донора» поют дважды (он же поёт в своей паре), а песни последнего в этом
   раунде не поёт никто.
5. Для каждой пары «исполнитель → поставщик» выбирается одна случайная песня из
   принесённых поставщиком.

Источник случайности — только `crypto.getRandomValues()` (на Workers доступен),
`Math.random()` не используем.

## 6. Архитектура

```
                webhook POST /webhook
Telegram ────────────────────────────▶ Worker (grammY webhookCallback)
                (проверка                  │  auth: env.ADMIN_IDS
                 X-Telegram-Bot-Api-       │  guards: активный своп, его состояние, режим
                 Secret-Token)             ▼
                                     handlers ──▶ db/repo.ts ──▶ D1 (SQLite)
                                            │
                     ответы участникам ◀────┘  (sendMessage / sendMessage в личку)
```

Структура проекта:

```
SongSwapBot/

│   └── e2e/run.mjs         — самодостаточный прогон всех сценариев (wrangler dev + мок Telegram)
├── migrations/
│   ├── 0001_init.sql       — схема из раздела 7
│   └── 0002_multiswap.sql  — один своп на чат + pending_intake
└── src/
    ├── index.ts            — entrypoint воркера: fetch → webhookCallback(bot), кеш бота в изоляте
    ├── bot.ts              — создание Bot, регистрация middleware и хендлеров
    ├── env.ts              — типы окружения (bindings, секреты, vars)
    ├── deps.ts             — BotDeps: repo + adminIds, общие зависимости хендлеров
    ├── admin.ts            — парсинг ADMIN_IDS
    ├── handlers/
    │   ├── songs.ts        — приём песен: /add, упоминание в группе, маршрутизация лички
    │   ├── status.ts       — /status (все мои свопы), /leave
    │   ├── admin.ts        — /newswap, /close, /draw, callback-роутер
    │   ├── choose.ts       — обработка выбора свопа кнопкой (pick:...)
    │   ├── shared.ts       — клавиатуры выбора + ядро приёма песен в своп
    │   └── misc.ts         — /start, /help, фолбэк на неизвестные команды/не-текст
    ├── logic/
    │   ├── draw.ts         — деранг + выбор песни (crypto.getRandomValues, без modulo bias)
    │   ├── swap.ts         — runDraw: атомарная запись + рассылка результатов
    │   └── notify.ts       — sendSafe/sendLongText (лимит 4096), русские плюрализации
    └── db/

        └── types.ts        — типы строк таблиц
```

Принципы:

- Вся работа с SQL — только в `db/repo.ts`; хендлеры не знают про таблицы.
- Один воркер, одна точка входа; grammY сама отвечает на webhook за ~миллисекунды,
  холодного старта нет.
- Приватность: секретный режим реализуется на уровне того, *что* бот рассылает и кому,
  а не шифрованием; в БД лежит минимум (id, имя, юзернейм, текст песни).

## 7. База данных (D1 / SQLite)

```sql
CREATE TABLE swaps (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  mode       TEXT    NOT NULL CHECK (mode IN ('public', 'secret')),
  chat_id    INTEGER NOT NULL,            -- чат, к которому привязан своп:
                                          -- членство (getChatMember) и анонсы
  title      TEXT,
  state      TEXT    NOT NULL DEFAULT 'collecting'
                     CHECK (state IN ('collecting', 'closed', 'drawn')),
  created_at TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE participants (
  swap_id      INTEGER NOT NULL REFERENCES swaps(id) ON DELETE CASCADE,
  user_id      INTEGER NOT NULL,
  display_name TEXT    NOT NULL,
  username     TEXT,
  joined_at    TEXT    NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (swap_id, user_id)
);

CREATE TABLE songs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  swap_id    INTEGER NOT NULL REFERENCES swaps(id) ON DELETE CASCADE,
  user_id    INTEGER NOT NULL,            -- кто принёс
  text       TEXT    NOT NULL,            -- «Исполнитель — Название»
  created_at TEXT    NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_songs_swap_user ON songs(swap_id, user_id);

CREATE TABLE assignments (
  swap_id          INTEGER NOT NULL REFERENCES swaps(id) ON DELETE CASCADE,
  singer_user_id   INTEGER NOT NULL,      -- кто поёт
  provider_user_id INTEGER NOT NULL,      -- чью песню поёт
  song_id          INTEGER NOT NULL REFERENCES songs(id),
  UNIQUE (swap_id, singer_user_id)
);

-- 0002: один активный своп на чат + отложенные песни из лички,
-- ожидающие выбора свопа кнопкой (не больше одной попытки на юзера)
CREATE UNIQUE INDEX idx_swaps_chat ON swaps(chat_id);

CREATE TABLE pending_intake (
  user_id    INTEGER PRIMARY KEY,
  text       TEXT    NOT NULL,
  created_at TEXT    NOT NULL DEFAULT (datetime('now'))
);
```

Инварианты:

- Один активный своп на чат (уникальный индекс `swaps.chat_id`): `/newswap` заменяет
  только своп своего чата, каскадно стирая его участников, песни и назначения.
- Участник существует ⇔ у него есть хотя бы одна песня (`/leave` удаляет и то и другое).
- В D1 foreign keys включены по умолчанию, `ON DELETE CASCADE` работает из коробки.

## 8. Конфигурация и деплой

Секреты и переменные (`wrangler.jsonc` + `wrangler secret`):

| Переменная | Тип | Значение |
|---|---|---|
| `BOT_TOKEN` | secret | токен от @BotFather |
| `WEBHOOK_SECRET` | secret | случайная строка для верификации вебхука |
| `ADMIN_IDS` | secret | Telegram user id админов через запятую, напр. `123456,654321` (секрет, чтобы не утекал в репозиторий) |

Шаги:

1. @BotFather → `/newbot` → токен. **Privacy mode не трогаем** (дефолт ON): боту в группе
   видны команды `/add@bot`, упоминания и ответы на его сообщения — этого достаточно.
2. Чтобы в группе работало простое `/add` без суффикса — сделать бота **админом группы**
   (тогда видны и общие команды).
3. `npm install`
4. `wrangler d1 create songswap` → id базы в `wrangler.jsonc`
5. `wrangler d1 migrations apply songswap --remote`
6. `wrangler secret put BOT_TOKEN` и `wrangler secret put WEBHOOK_SECRET`
7. `wrangler secret put ADMIN_IDS` — Telegram user id админов через запятую
8. `wrangler deploy`
9. Один раз повесить вебхук:

   ```bash
   curl "https://api.telegram.org/bot$BOT_TOKEN/setWebhook" \
     -d "url=https://<имя-воркера>.<аккаунт>.workers.dev/webhook" \
     -d "secret_token=$WEBHOOK_SECRET"
   ```

10. Добавить бота в группу, проверить.

Локальная разработка без настоящего Telegram (весь сценарий прогоняется фейковыми апдейтами):

1. `cp .dev.vars.example .dev.vars` — там фейковые токены и `BOT_INFO_JSON`
   (подставной getMe, чтобы воркер не ходил в Telegram API при старте).
2. `npm run db:migrate:local`
3. `python3 scripts/mock-telegram.py` — мок Bot API на `127.0.0.1:8788`;
   всё, что бот отправляет, пишется в `/tmp/telegram-mock.log`.
4. `npx wrangler dev --port 8787 --var TELEGRAM_API_ROOT:http://127.0.0.1:8788`
5. Скармливаем боту фейковые апдейты (важно: grammY матчит команды по entity
   `bot_command`, как и настоящий Telegram):

   ```bash
   curl -X POST http://localhost:8787/webhook \
     -H "Content-Type: application/json" \
     -H "X-Telegram-Bot-Api-Secret-Token: dev-secret" \
     -d '{"update_id":1,"message":{"message_id":1,"from":{"id":111,"is_bot":false,"first_name":"A"},"chat":{"id":111,"type":"private","first_name":"A"},"date":1,"text":"/newswap тест","entities":[{"offset":0,"length":8,"type":"bot_command"}]}}'
   ```

6. Состояние БД смотрим так:
   `npx wrangler d1 execute songswap --local --command "SELECT * FROM swaps"`.

Для живого теста с настоящим Telegram — деплоим (бесплатный тариф это позволяет)
или поднимаем туннель (cloudflared / ngrok): локальный `wrangler dev` сам по себе
недоступен из интернета.

## 9. Тесты

Всё разом (регресс перед деплоем): `npm test`.

**Юнит-тесты** — `npm run test:unit` (vitest, без воркера):
- алгоритм жеребьёвки: инварианты взаимных пар при чётном/нечётном n (2–9, по 200 итераций);
- русские плюрализации, нарезка длинных сообщений по лимиту Telegram, «глотание» ошибок отправки;
- парсинг `ADMIN_IDS`, байтовая обрезка `callback_data`.

**E2E** — `npm run test:e2e` (`tests/e2e/run.mjs`):
сам поднимает мок Telegram API (`:8788`) и `wrangler dev` (`:8787`), применяет миграции,
сбрасывает локальную D1 и прогоняет сценарии фейковыми апдейтами, сверяя базу и все
исходящие сообщения бота:

1. полный цикл публичного свопа: создание, три канала сдачи песен, дубликаты, `/leave`,
   права, закрытие (без дубля анонса), жеребьёвка при нечётном числе, личные сообщения,
   таблица, `/status` с жребием, перерозыгрыш, destructive `/newswap`, отказ при < 2 участников;
2. секретный режим с якорем в группе: создание `/newsecret`, чужак не вступает,
   заявки из группы переадресуются в личку, приватность `/status`, личные результаты
   и нейтральная строка в чат;
3. параллельные свопы в двух группах: изоляция данных, кнопки выбора при неоднозначности
   (песни, `/leave`, приватные `/close`/`/draw`), scoped-замена свопа, перерозыгрыш;
4. гварды: пустой `/add`, не-админские команды, неизвестные команды, не-текст, редирект
   `/status`, неверный секрет вебхука (401), чужой путь (404);
5. членство: чужак (не участник чата свопа) не вступает ни текстом в личку,
   ни кнопкой выбора свопа.

Раннер самовосстанавливается: если dev-воркер упал (workerd изредка молча умирает),
он перезапускает стенд и повторяет апдейт — все мутирующие операции бота атомарны,
а состояние живёт в локальной D1. Порты 8787/8788 должны быть свободны; лог wrangler
пишется в `$TMPDIR/songswap-e2e-wrangler.log`.
